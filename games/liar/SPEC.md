# 라이어 게임 (Englknight) — 제작 스펙 v1

> 원본 자료: `REFERENCE_라이어게임.txt` (사용자 제공 메커니즘 정리)
> 이 스펙은 그 자료를 **정적 웹사이트 / 한 기기 패스 앤 플레이**로 옮기기 위해 확정한 것이다.

## 0. 왜 패스 앤 플레이인가
라이어게임의 핵심(설명 라운드·토론)은 **말로 하는 오프라인 대화**다.
그래서 이 게임은 온라인 멀티가 필요 없다 — 한 기기를 돌려가며
"제시어 확인 / 비밀 투표 / 판정"만 앱이 맡고, 설명과 토론은 사람이 직접 한다.
마피아와 달리 서버 권위 문제도 없다. GitHub Pages 정적 배포로 100% 성립한다.

- 대상: 한자리에 모인 3~10명, 기기 1대
- 앱의 역할: 역할 배정 · 제시어 비공개 전달 · 순서/타이머 · 비밀 투표 · 승패 판정 · 점수판

## 1. 인원·역할
| 항목 | 값 |
|---|---|
| 인원 | 3~10명 (권장 4~8) |
| 라이어 | 기본 1명. 인원 6명 이상이면 "라이어 2명" 옵션 선택 가능 |
| 시민 | 나머지 전원 |

- 이름은 기본값 `플레이어 1..N`, 사용자가 수정 가능(최대 6자).
- 역할은 매 라운드 무작위 재배정.

## 2. 모드 (v1 범위)
| 모드 | 라이어 화면 | 비고 |
|---|---|---|
| **기본** | "당신은 라이어입니다" + 주제만 표시 | 기본값 |
| **바보 모드** | 같은 주제의 **다른 제시어**를 보여줌 | 라이어는 자신이 라이어인 줄 모른다. 결과 화면에서 진실 공개 |
| **스파이 모드** | (라이어는 기본과 동일) 시민 1명이 **스파이** — 제시어와 "라이어는 OOO입니다"를 함께 봄 | 스파이는 라이어와 함께 승패를 공유. **5인 이상에서만 선택 가능**(검수 중 확정) |

- **배신자 모드는 v1 범위 밖**(백로그). 설정 화면에 노출하지 않는다.
- **스파이 모드 최소 인원 5명** (2026-08-28 검수에서 추가 확정): 4인 이하에서는 라이어+스파이가 시민 수와 같거나 많아져
  시민이 투표로 라이어를 이길 수 없다(3인이면 진짜 시민이 1명뿐). 4인 이하에서는 스파이 버튼을 비활성화하고,
  저장된 설정이 조건을 어기면 기본 모드로 되돌린다.
- 바보 모드에서 라이어가 지목당했을 때의 "추리 찬스"는 그대로 준다
  (자기가 라이어였다는 사실을 그 시점에 알려주고 제시어를 고르게 한다).

## 3. 진행 순서 (Phase)
```
설정 → 역할확인(돌려보기) → 설명 라운드 → 토론 → 비밀투표 → 개표
      → (지목 성공 시) 라이어 추리 → 결과 → 다음 라운드
```

### (1) 설정 `setup`
- 인원 수 / 이름 입력
- 주제 선택: 카테고리 다중 선택 또는 "랜덤"
- 모드 선택 (기본 / 바보 / 스파이)
- 라이어 수 (1 / 2 — 6인 이상일 때만)
- 설명 라운드 바퀴 수 (1바퀴 / 2바퀴)
- 토론 시간 (1분 / 2분 / 3분 / 무제한)
- 추리 보기 개수 (4 / 6 / 8, 기본 6)
- 설정은 `localStorage`에 저장해 다음 판에 그대로 복원한다.

### (2) 역할 확인 `reveal` — **가장 중요한 화면**
기기를 한 사람씩 넘긴다. 옆사람이 못 보게 하는 게 핵심.
1. 커버 화면: "**OOO님 차례입니다** — 다른 사람은 보지 마세요" + [내 카드 보기]
2. 카드 공개: 시민 → `주제: 음식` / `제시어: 김치찌개`
   라이어(기본) → `주제: 음식` / `당신은 라이어입니다`
   라이어(바보) → 시민과 똑같은 형식으로 **다른 제시어**
   스파이 → 제시어 + `라이어: OOO`
3. [확인했습니다 · 다음 사람에게] → 즉시 커버 화면으로 복귀
- 카드는 **탭해서 여는 방식**이 아니라 **누르고 있는 동안만 보이는 방식**도 좋다(선택 구현).
  단 어느 쪽이든 "다음"을 누르면 화면에 아무 정보도 남지 않아야 한다.
- 마지막 사람까지 끝나면 자동으로 설명 라운드로.

### (3) 설명 라운드 `describe`
- 시작 플레이어 **무작위**(라이어가 항상 첫 순서면 불리하므로 반드시 랜덤).
- 화면에는 현재 발언자 이름 + 남은 순서 목록 + "다음 사람" 버튼.
- 1인당 제한시간 옵션(끄기 / 15초 / 30초) — 켜면 카운트다운.
- 설정한 바퀴 수만큼 반복.
- **제시어는 이 화면에 절대 표시하지 않는다** (기기를 모두가 보는 상태).

### (4) 토론 `debate`
- 큰 타이머 + [투표 시작] 버튼(언제든 조기 종료 가능).

### (5) 비밀 투표 `vote`
- 다시 기기를 돌린다. 커버 → "OOO님, 라이어로 의심되는 사람을 고르세요"
  → 자기 자신 제외한 목록에서 1명 선택 → 다음 사람.
- 각자 무엇을 골랐는지는 개표 전까지 화면에 남기지 않는다.

### (6) 개표 `tally`
- 득표수 공개(누가 누구를 찍었는지도 함께 공개 — 오프라인 파티에선 이게 재미다).
- **동률**이면: 재투표 1회 → 그래도 동률이면 **라이어 승리**.
- 최다 득표자가 라이어면 → (7)로. 아니면 → 결과(라이어 승).

### (7) 라이어 추리 `guess`
- 라이어 본인에게 기기를 준다.
- 같은 주제에서 뽑은 **보기 N개(정답 1 + 오답 N-1)** 중 하나 선택.
  (오답은 그 주제 단어 풀에서 무작위, 이번 판에 쓰인 다른 제시어와 겹치지 않게)
- 라이어 2명이면 순서대로 각각 1번씩, **한 명이라도 맞히면 라이어팀 역전승**.
- 제한시간 30초(옵션으로 끄기).

### (8) 결과 `result`
- 승패 문구 + 정답 제시어 + 라이어(및 스파이) 정체 전원 공개
- 바보 모드였다면 "라이어에게는 `OOO`가 보였습니다" 공개
- 점수 갱신 후 점수판 표시, [다음 라운드](같은 인원·설정 유지, 역할 재배정) / [설정으로]

## 4. 승리 조건 (원본 4번 그대로)
| 케이스 | 결과 |
|---|---|
| 투표로 라이어를 못 맞힘 | **라이어 승리** |
| 라이어를 맞혔고, 라이어가 제시어를 맞힘 | **라이어 역전승** |
| 라이어를 맞혔고, 라이어가 틀림 | **시민 승리** |
- 스파이 모드의 스파이는 라이어와 같은 편(라이어 승/역전승 시 함께 승리).

## 5. 점수판
| 상황 | 점수 |
|---|---|
| 라이어 승리(지목 실패) | 라이어(+스파이) 각 **+2** |
| 라이어 역전승 | 라이어(+스파이) 각 **+1** |
| 시민 승리 | 시민 각 **+1** |
| 라이어를 지목한 시민 | 추가 **+1** (지목 성공 시에만) |
- 세션 내 누적, 결과 화면과 설정 화면에서 확인 가능. `localStorage` 저장.

## 6. 제시어 데이터
- 카테고리 **8개 이상**: 음식 / 동물 / 장소 / 영화·드라마 / 직업 / 스포츠 / 물건 / 인물·캐릭터
- 카테고리당 **최소 30개** 단어 (총 240개 이상)
- 난이도 밸런스: 너무 추상적이거나(설명 불가) 너무 유명해서 한 마디에 특정되는 단어는 피한다.
- 한국인 파티 기준 상식 범위. 특정 지역·연령대만 아는 단어 금지.
- 코드 상단 `const WORDS = { 음식: [...], ... }` 형태로 한 곳에 모아 수정하기 쉽게 한다.

## 7. UI/기술 요건 (허브 공통 규칙)
- **단일 파일** `games/liar/index.html` (HTML+CSS+JS 인라인). 외부 라이브러리·CDN·폰트 금지.
- `file://` 더블클릭으로도 동작해야 한다 (fetch / ES module import 금지).
- 다크 아케이드 테마, 기존 게임과 톤 통일:
  `--bg:#0a0d16; --panel:#141a2b; --panel2:#1b2338; --line:#28324f; --text:#e8ecf7; --muted:#8b95b3`
  라이어 액센트는 **보라 계열 `--accent:#a97bff`** + 보조 `--gold:#ffd166` (테트리스=시안, OX=민트/레드, 마피아=레드와 구분)
- 모바일 세로 우선: `max-width:460px` 스테이지, `env(safe-area-inset-*)` 대응, `100dvh`
- 좌상단에 허브 복귀 링크 `../../index.html`
- 규칙 설명(도움말) 모달 1개 — 진행 순서·승리 조건·모드 요약
- 하단에 버전 표기 `v1.0.0`
- 진행 중 새로고침하면 판이 초기화된다 → 게임 중 `beforeunload` 경고 1회
- 사운드 없음

# 라이어 게임 — 온라인 멀티 모드 스펙 v1.1 (2026-08-28 사용자 지시)

> 사용자 지시: "다같이 실제로 들어와서 게임 안에서 실제로 게임을 하는거지.
> 한사람만 다른 단어/라이어 주고 채팅으로 돌아가게"

## M0. 위치 — 기존 모드는 그대로 둔다
첫 화면에서 **① 한 기기로(패스 앤 플레이)** / **② 온라인으로** 를 고른다.
①은 지금 배포된 v1.0.1 그대로다. 건드리지 않는다. ②를 새로 만든다.

## M1. 통신 — 캐치마인드 방식 재사용
- `games/catchmind/net.js`의 MQTT 계층(공용 브로커 다중화 + 자동 승격 + 토픽 해싱)을
  **`games/liar/net.js`로 복사해서 쓴다.** 캐치마인드 폴더는 다른 담당 관할이라 직접 참조하지 않는다.
- 방 코드 6자리 → 토픽은 `SHA-256(코드+salt)` (코드만으로 토픽을 추측하지 못하게).
- mqtt.js는 CDN 로드. 허브 가이드라인의 "CDN 금지"는 허브 파일 한정이며
  게임 폴더에는 적용되지 않는다(OX 선례, 홈페이지 담당이 정정 확인).

## M2. **비밀 유지 — 이 모드의 핵심 난제**
공용 브로커는 **같은 방의 누구나 모든 메시지를 볼 수 있다**(개발자도구). 제시어를 그대로
브로드캐스트하면 라이어가 그냥 읽는다. 게임이 성립하지 않는다.

**해법: WebCrypto 종단 암호화.**
1. 각 참가자는 입장 시 키쌍을 생성하고 **공개키만** 방에 알린다 (ECDH P-256 + AES-GCM 권장, RSA-OAEP도 가능).
2. 방장이 역할을 배정한 뒤, **참가자별로 그 사람의 공개키로 암호화해서** 개인 배정 메시지를 보낸다.
3. 각자 자기 개인키로만 복호화된다. 다른 참가자는 브로커 메시지를 봐도 읽지 못한다.
4. `crypto.subtle`은 보안 컨텍스트에서만 동작한다. **사용 불가 환경(file:// 등)에서는
   온라인 모드를 열지 말고** "온라인 모드는 https 주소로 접속해야 합니다"를 안내한다.
   (배포본은 https라 정상. 패스 앤 플레이는 그대로 쓸 수 있다.)

**남는 한계 — 방장은 안다.** 서버가 없으므로 배정을 누군가의 브라우저가 해야 하고,
그건 방장이다. 방장이 개발자도구를 열면 누가 라이어인지 볼 수 있다.
- 기본값: 방장도 참가한다(친구끼리 하는 파티 게임 전제).
- **옵션: "방장은 진행만 하기"** — 켜면 방장은 역할을 받지 않고 진행·관전만 한다.
  완전히 공정한 판이 필요할 때 쓴다.
- 이 한계는 규칙 시트에 한 줄로 솔직히 적는다. 숨기지 않는다.

## M3. 진행 (온라인)
```
로비 → 역할 배정 → 설명 라운드(채팅) → 자유 토론(채팅) → 비밀 투표
     → 개표 → (지목 성공 시) 라이어 추리 → 결과 → 다음 라운드
```

### (1) 로비
- **방 만들기** → 6자리 코드 발급 / **참여하기** → 코드 입력
- 닉네임(최대 6자), 3~10명. 방장이 설정을 정한다(주제·모드·라이어 수·설명 바퀴·발언 제한·토론 시간·추리 보기 수 — 패스 앤 플레이와 같은 항목)
- 참가자 목록 실시간 갱신, 방장만 [시작]
- 방 코드 복사 버튼

### (2) 역할 배정
- 각자 자기 화면에만 `주제 + 제시어` 또는 `당신은 라이어입니다` 표시 (M2 암호화 경로)
- 바보 모드면 라이어에게 다른 제시어, 스파이 모드면 스파이에게 라이어 정체까지
- 전원 "확인" 누르면 설명 라운드로 (방장이 진행)

### (3) 설명 라운드 — **채팅**
- 순서는 무작위. **자기 차례에만 입력창이 열린다.** 다른 사람은 읽기만.
- 한 사람이 한 번에 한 문장(최대 60자). 보내면 다음 사람으로 자동 이동.
- 1인 발언 제한시간(끄기/15초/30초). 시간 초과 시 "(시간 초과)"로 넘어간다.
- 설정한 바퀴 수만큼 반복.
- **제시어는 이 화면 어디에도 표시하지 않는다** — 자기 카드는 접힌 버튼으로 다시 볼 수 있게 한다(자기 것만).

### (4) 자유 토론 — 채팅
- 전원 자유 입력. 타이머(1/2/3분/무제한). 방장은 [투표 시작]으로 조기 종료 가능.

### (5) 비밀 투표
- 각자 자기 화면에서 1명 지목(자기 자신 제외). 방장에게 **암호화해서** 보낸다.
- 몇 명이 투표했는지만 표시하고, 누가 누구를 찍었는지는 개표 전까지 공개하지 않는다.

### (6) 개표
- 방장이 집계해 전체에 공개(득표수 + 누가 누구를 찍었는지).
- 동률 → 후보만 대상으로 재투표 1회 → 그래도 동률이면 라이어 승리. (패스 앤 플레이와 동일)

### (7) 라이어 추리
- 지목된 라이어 화면에만 보기 N개가 열린다. 나머지는 대기 화면.
- 라이어 2명이면 순서대로, 한 명이라도 맞히면 역전승. 제한 30초.

### (8) 결과
- 승패·정답·라이어(및 스파이) 정체 공개, 점수 갱신, 방장이 [다음 라운드]
- **점수는 방 안에서만 누적**한다(닉네임 기준). 패스 앤 플레이의 로컬 점수판과 섞지 않는다.

## M4. 이탈·재접속
- 참가자 이탈: 목록에서 제거하고 채팅에 알린다. 진행 중이면 그 사람 차례는 건너뛴다.
- **라이어가 나가면** 그 판은 무효 → 결과 화면에 "라이어가 나가 판이 종료됐습니다" 후 로비로.
- **방장이 나가면** 방을 닫는다(전원에게 알리고 로비로). 방장 이양은 v1.1 범위 밖.
- 인원이 3명 미만이 되면 진행 중단 → 로비.
- 브로커 절단은 캐치마인드와 같은 방식으로 다음 브로커 승격.

## M5. UI
- 채팅 로그가 주 화면(마피아와 비슷한 레이아웃). 상단에 페이즈·타이머·참가자 목록, 하단에 입력창.
- 내 역할 카드는 **접힌 상태**로 두고 눌러야 펼쳐진다 — 옆에 사람이 있을 수 있다.
- 나머지 디자인 규칙은 v1.0.1과 동일(다크 아케이드, 보라 액센트, 460px, 44px 터치, 버전 시트).
