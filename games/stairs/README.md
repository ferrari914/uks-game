# 무한의 계단 (Infinite Stairs)

버튼 두 개로 계단을 무한히 오르는 아케이드. 혼자 최고 층수에 도전하는 **싱글**과,
한 명 남을 때까지 겨루는 **멀티**가 있다.

- 스펙: [SPEC.md](SPEC.md) — 수치·규칙의 근거는 전부 여기 있다
- 원작 조사: [REFERENCE_무한의계단.txt](REFERENCE_무한의계단.txt) (게임 관리자 작성)
- 파일: `index.html` + 공용 `../shared/ranking.js`. classic script만 쓰므로 **더블클릭(`file://`)으로도 열린다.**

## 조작

| | |
|---|---|
| **오르기** | 지금 바라보는 방향 그대로 한 칸 |
| **방향 전환** | 몸을 돌리면서 **동시에** 한 칸 |

다음 계단이 지금 방향과 **같으면 오르기**, **반대면 방향 전환**. 잘못 누르면 벽에 부딪혀 즉사한다.

- PC: `Z`·`↑` = 오르기 / `X`·`←`·`→` = 방향 전환
- 모바일: 화면 아래 왼쪽 = 방향 전환, 오른쪽 = 오르기

## 체력 게이지

가만히 있으면 닳고, 한 칸 오를 때마다 회복한다. **멈추면 죽는다.**

```
초당 감소 D(f) = 22 + 53 × ∛( min(1, f/2000) )      한 칸당 회복 +13
```

| 층 | 1초 망설이면 | 유지에 필요한 속도 |
|---|---|---|
| 1 | −26% | 2.0 칸/초 |
| 50 | −38% | 2.9 칸/초 |
| **300** | **−50%** | 3.9 칸/초 |
| 700 | −59% | 4.6 칸/초 |
| 2000 이상 | −75% (상한) | 5.8 칸/초 |

기준점은 **300층에서 1초 망설이면 게이지 절반**(사용자 확정). 수치는 `index.html` 상단
`TUNE` 한 곳에 모여 있고, 손맛 조정은 **회복량 12**를 먼저 만지면 전 구간이 함께 움직인다.

세제곱근 곡선이라 **난이도가 초반에 몰린다.** 완벽하게 정확히 눌렀을 때 도달 층수:

| 연타 속도 | 도달 |
|---|---|
| 2 칸/초 | 30층 |
| 2.5 칸/초 | 70층 |
| 3 칸/초 | 153층 |
| 3.5 칸/초 | 299층 |
| 4 칸/초 | 529층 |
| 4.5 칸/초 | 865층 |
| 5 칸/초 | 1329층 |

5.8칸/초 이상을 실수 없이 **유지**하면 이론상 죽지 않는다 — 2000층에서 감소량에 상한이
있기 때문이다(원작도 그렇다). 실제로는 그 속도에서 방향 판단이 먼저 무너진다.

## 랭킹

두 겹이다. **주력은 "내 기록"이고 명예의 전당은 덤이다.**

- **내 기록** — 이 기기의 `localStorage`. 오프라인에서도 항상 동작한다. 싱글·멀티 모두 남는다
- **명예의 전당 / 주간 / 일간** — `games/shared/ranking.js` 공용 모듈이 담당한다.
  게임은 `RANK.autoSubmit`·`RANK.board` 두 줄만 부르고, DB 주소도 스키마도 모른다
- **등재는 자동이다.** 등록 버튼이 없다. 다만 **자기 기록을 갱신했을 때만** 실제로 보낸다 —
  끝날 때마다 무조건 쓰면 한 사람이 순위표를 혼자 채우고, 기록은 지울 수도 없다
- **이름은 시작 전에 한 번 받는다.** 자동 등재라 끝난 뒤에 물을 자리가 없다.
  이름이 없으면 게임 버튼이 잠긴다. **이름은 게임 사이에 공유된다**
- **주간은 월요일 0시, 일간은 매일 0시에 새로 시작한다 (한국시간 고정).**
  브라우저 시계를 쓰지 않는다 — 해외 접속자가 다른 "오늘"을 보면 순위가 갈라진다
- **초기화는 삭제가 아니다.** 날짜 칸이 바뀔 뿐, 지난 기록은 그대로 남는다
- 순위판을 못 불러와도 **게임에는 영향이 없다**

### 한계 (숨기지 않는다)

- 클라이언트가 자기 점수를 직접 올리는 구조라 **검증되지 않는다**
- 이름은 신원이 아니라, 다른 사람이 같은 이름을 쓰면 한 줄로 합쳐진다
- **서버 색인(`["score","dk","wk"]`)이 있어야 주간·일간이 뜬다.** 없으면 그 두 탭만
  오류를 표시하고, 명예의 전당과 게임은 정상 동작한다
- 이관(2026-09-02) 전 기록 12건은 날짜 필드가 없어 **명예의 전당에만** 남는다
- **한 번 올린 기록은 수정·삭제할 수 없다.** 서버 규칙이 추가만 허용한다 —
  남의 기록을 지울 수 없게 하려는 것이지만, 잘못 올려도 되돌릴 수 없다는 뜻이기도 하다
- 위 두 가지는 게임 안 명예의 전당 옆에도 한 줄로 적어 두었다
- 2026-09-01 이전에는 공용 MQTT 브로커의 retain 슬롯을 썼다. 그 브로커는 테스트용이라
  주기적으로 정리돼 **기록이 사흘을 못 넘겼다.** 그래서 옮겼다

## 멀티플레이

- 2~8인. 방 코드 5자로 입장. 공용 MQTT 3중 브로커 폴백(OX 서바이벌과 같은 구조)
- **전원이 완전히 같은 계단을 오른다.** 방장이 시드를 뿌리고 모두 같은 난수열을 만든다 —
  실력 경쟁에 패턴 운이 섞이지 않게 하기 위해서다
- 각자 400ms마다 층수·생존 여부를 발행한다. 죽는 순간에는 즉시 알린다.
  **6초간 소식이 없으면 이탈로 보고 탈락 처리**한다
- 탈락하면 **즉시 관전**으로 넘어가고 최종 층수가 고정된다
- 마지막 한 명이 남으면 끝. 동시에 사라지면 **최종 층수가 높은 쪽이 우승**, 층수까지 같으면 공동 우승
- 결과 순위는 **오래 버틴 순**이다 — 더 높이 올라갔어도 먼저 떨어지면 아래에 놓인다
- **방장이 나가도 경기는 계속된다.** 각자의 죽음은 본인만 보고하고 다툴 여지가 없어서,
  시작 이후에는 모든 클라이언트가 같은 상태로 승자를 독립 계산한다.
  방장 권한은 대기실과 시작 신호까지만 필요하다

### 신뢰 모델 — 친구끼리 하는 방 전제

부정 방지를 하지 않는다. 두 경로가 열려 있다.

1. **가짜 층수 발행** — 공용 MQTT라 마음먹으면 아무 숫자나 보낼 수 있다
2. **관전자 코칭 / 계단 암기** — 전원이 같은 계단을 오르므로, 먼저 죽은 사람이 옆에서
   "다음은 왼쪽!"이라고 불러주면 그대로 통한다.
   그래서 **관전 화면에는 생존자의 앞으로 올 계단을 그리지 않는다**(층수와 생존 여부만 보여준다).
   다만 죽기 전까지 본 구간을 기억하는 것은 막을 수 없다

## 기술 메모

- 외부 의존은 mqtt.js CDN 하나뿐이고, **멀티를 고르거나 명예의 전당을 열 때만** 불러온다.
  **플레이 중에는 네트워크를 전혀 건드리지 않는다**
- 오가는 값이 층수와 생존 여부뿐이라 암호화할 것이 없다 → `crypto.subtle`을 쓰지 않고,
  따라서 https가 아니어도 된다
- 게이지는 프레임이 아니라 **실제 시계**로 닳는다. `requestAnimationFrame`에 물려두면
  탭을 옮겨둔 동안 게이지가 얼어붙어 안 죽는다 — 그건 이 게임의 규칙이 아니다
- 입력은 애니메이션 중에도 막지 않는다. 논리 상태를 즉시 갱신하고 그림이 따라온다
- **탭이 숨겨지면 캔버스 크기가 0이 된다.** 그대로 그리면 `H*1.6` 으로 나누는 곳에서
  NaN 이 나와 예외로 죽는다. 크기가 0이면 그리기를 건너뛰고, 화면이 다시 보일 때
  크기를 다시 잡는다 — **대기실에서 다른 탭을 보다가 방장이 시작하면 실제로 터지던 자리다**
- **배경은 우주다.** 성운(방사형 그라데이션 3겹)·별 3겹·먼 행성은 매 프레임 다시 그릴
  필요가 없어 **오프스크린 캔버스에 한 번만 그려두고 복사**한다. 별과 유성만 매 프레임
  움직인다. 유성은 4.5~13.5초 간격으로 무작위로 지나간다
- **고도에 따라 하늘이 변한다** — 0층 대기권 → 60층 우주 → 250층 성운 → 600층 은하 띠
  → **1000층 은하 중심**. 배경 팔레트를 층수로 보간하고, 12층쯤 바뀔 때마다 오프스크린을
  다시 그린다. **하늘 구간 상한(1000층)과 난이도 상한(2000층)은 다른 값이다** — 오타가 아니라,
  하늘이 최종 단계에 닿은 뒤에도 난이도는 2000층까지 계속 오른다. 층수 자체가 보상이 되게 하는 장치다.
  처음에는 은하 중심을 2000층에 뒀는데 **아무도 거기까지 못 갔다**(실제 최고 431층).
  2026-09-02 전 구간을 절반으로 당겼다 — 보상은 닿을 수 있는 자리에 있어야 한다
- **소리는 Web Audio 로 합성한다** — 음원 파일을 넣으면 `file://` 요건과 파일 하나 관례가
  깨지고 로딩도 생긴다. 짧은 발음 몇 개라 오실레이터로 충분하다.
  브라우저가 첫 입력 전에는 소리를 막으므로 AudioContext 는 그때 만들어진다
- **주인공은 우주비행사다.** 방향은 두 가지로 알린다 — ①금색 바이저가 헬멧 앞쪽으로
  치우쳐 있고 ②등짐이 뒤로 튀어나와 실루엣이 비대칭이다. 어느 하나만으로는
  작은 화면에서 안 읽힌다
- **계단은 2D 평면이다** (2026-09-02 사용자 확정). 모든 칸이 같은 크기·같은 간격이고
  멀다고 바래지지도 않는다. **깊이는 계단이 아니라 배경이 맡는다** — 성운·별 3겹 시차·행성.
  계단 자체는 조명(윗면 밝음 / 앞면 어두움)과 형광 띠로만 읽힌다.
  ※ 원근을 빼면 멀리 있는 칸이 중앙으로 모이지 않아 좌우로 드리프트하다 화면 끝에서
  뭉텅 잘린다. 그래서 **가장자리에서 흐려지게** 했다 — 3D 시절 공기원근이 하던 일이다
- **그림 파일을 한 장도 쓰지 않는다.** 화면은 전부 캔버스로 그린다.
  `file://` 로 열려야 하고 게임 파일을 `index.html` 하나로 유지해야 해서 고른 방식이다
- 렌더 비용은 **한 프레임 0.16ms**다(300층, 우주 배경·별·행성 포함, 데스크톱 측정). 60fps 예산 16.7ms의 1% —
  초당 6회 연타에도 그림이 밀릴 여지가 없다
