# 무한의 계단 (Englknight) — 제작 스펙 v1

작성: 무한의 계단 담당 / 2026-08-28
근거: `REFERENCE_무한의계단.txt` (게임 관리자 조사) + 사용자 확정 요구사항
검수: 게임 관리자

---

## 0. 이 게임이 이 환경에 맞는 이유

플레이어끼리 **충돌 판정이 없다.** 각자 자기 계단을 독립적으로 오르므로 실시간 위치
동기화가 필요 없고, 공유할 것은 "현재 층수 / 생존 여부" 두 개뿐이다.
그래서 GitHub Pages 정적 배포 + 공용 MQTT 조합으로 무리 없이 굴러간다.

파일은 프로젝트 관례대로 **`games/stairs/index.html` 단일 파일**로 만든다.

## 1. 조작 (게임의 전부)

버튼 2개. 원작과 동일하다.

| 액션 | 하는 일 |
|---|---|
| **오르기** | 지금 바라보는 방향 그대로 한 칸 올라간다 |
| **방향 전환** | 몸을 반대로 돌리면서 **동시에** 한 칸 올라간다 |

판단 규칙: 다음 계단이 지금 방향과 **같으면 오르기**, **반대면 방향 전환**.

- PC: `Z` = 오르기, `X` = 방향 전환 (원작 키). `↑`도 오르기, `←`/`→`도 방향 전환으로 함께 받는다.
- 모바일: 화면 아래 절반을 좌우로 나눈 큰 버튼 2개. **왼쪽 = 방향 전환, 오른쪽 = 오르기**.
  설정에서 좌우를 바꿀 수 있다(왼손잡이 대응).
- 입력은 애니메이션 중에도 막지 않는다. 한 칸짜리 **입력 큐**를 두고 즉시 소비한다
  (고층에서 초당 6회 이상 눌리므로, 입력이 씹히면 그대로 억울한 죽음이 된다).

## 2. 계단 생성

- 계단은 `L`/`R` 방향의 무한 수열이다. **다음 칸이 방향을 바꿀 확률 = 0.5** (고정).
  층수에 따라 패턴 난이도를 올리지 않는다 — 난이도는 게이지가 담당한다(원작과 동일).
- 시드 기반 PRNG(mulberry32)로 생성한다. 멀티에서 **전원이 같은 시드**를 쓰므로
  모두가 완전히 같은 계단을 오른다(공정성).
- 앞으로 20칸까지 미리 만들어 두고 렌더한다.

## 3. 체력 게이지 (수치 확정 — 원작에 공개 수치가 없어 직접 정함)

**기준점은 사용자 지시다: 300층에서 1초 망설이면 게이지 절반이 날아간다.**
(2026-08-28 사용자 지시로 초안보다 대폭 상향. 초안은 700층에서 2.5초여서 너무 여유로웠다)

- 게이지 범위 **0 ~ 100**, 시작 100.
- **첫 입력 전까지는 닳지 않는다** (준비 시간). 첫 칸을 오르는 순간부터 감소 시작.
- 한 칸 오를 때마다 **+12** 회복 (상한 100). 층수와 무관하게 일정.
- 초당 감소량 `D(f)` — `f` = 현재 층수:

  ```
  D(f) = 22 + 53 × ∛( min(1, f / 2000) )     [%/초]
  ```

  | 층 | D | 1초 망설임 | 유지에 필요한 속도 (D/12) | 가만히 있으면 |
  |---|---|---|---|---|
  | 0 | 22.0 %/s | −22% | 1.8 칸/초 | 4.5초 |
  | 50 | 37.5 %/s | −38% | 3.1 칸/초 | 2.7초 |
  | 100 | 41.5 %/s | −42% | 3.5 칸/초 | 2.4초 |
  | **300** | **50.2 %/s** | **−50%** | 4.2 칸/초 | 2.0초 |
  | 500 | 55.4 %/s | −55% | 4.6 칸/초 | 1.8초 |
  | 700 | 59.4 %/s | −59% | 5.0 칸/초 | 1.7초 |
  | 1200 | 66.7 %/s | −67% | 5.6 칸/초 | 1.5초 |
  | 2000 이상 | 75.0 %/s (상한) | −75% | 6.3 칸/초 | 1.3초 |

  세제곱근 곡선을 고른 이유: 사용자 기준점(300층 −50%)을 정확히 통과하면서
  2000층에서 상한에 닿아야 한다(자료의 "2000층 이상 일정"). 지수를 1/3로 두면
  초반 100층 안에서 난이도가 급히 올라붙고 그 뒤로는 완만해진다 —
  **초반부터 손을 놓을 틈이 없고, 고층은 이미 빠른 상태에서 조금씩 더 조인다.**
- 회복량을 4 → 12로 올린 것은 필수다. 감소가 50%/s인데 회복이 4면 유지에 12.5칸/초가
  필요해 사람이 칠 수 없는 속도가 된다. 12로 두면 300층 유지 속도가 4.2칸/초 —
  빡세지만 사람이 칠 수 있는 선이다.
- 게이지가 0이 되면 게임 오버.
- **게이지에는 여유가 없다.** 300층에서 가득 채워도 2초면 바닥이다. 멈추면 죽는다는
  원작의 감각이 여기서 나온다.
- 수치는 전부 파일 상단 `TUNE` 객체 한 곳에 모은다. 플레이 테스트 후 조정 가능하며,
  **가장 먼저 만질 손잡이는 회복량(12)이다** — 이 값 하나로 전 구간 유지 속도가 같이 움직인다.

## 7. 싱글플레이

- 혼자 오른다. 죽으면 최종 층수와 **랭킹 반영 결과**를 보여준다.
- **명예의 전당(전체 순위표)은 v1 필수다** — 사용자 확정, 2026-08-28.
  ("전체순위표 무조건 넣어줘") 빼거나 뒤로 미루는 선택지는 없다.
- 랭킹은 두 겹이다:
  - **내 기록** (localStorage) — 최고 기록 + 최근 상위 5개. 오프라인에서도 항상 동작한다.
  - **명예의 전당** (전체 상위 20명) — **Firebase Realtime Database** (2026-09-01 이관).
    SDK도 API 키도 쓰지 않고 REST + `fetch` 만 쓴다 — 외부 스크립트를 안 불러와야
    `file://` 요건과 "게임당 파일 하나" 관례가 유지된다.
    `Origin: null` 로도 CORS 가 열려 있어 `file://` 에서도 호출된다(실측 확인).
    경로는 `/ranking/stairs`, 스키마는 `{name(1~12자), score(정수), ts}` 이고
    **서버 규칙이 형식을 강제**한다 — 벗어나면 거부된다.
    **추가만 되고 수정·삭제는 아무도 못 한다** (남의 기록을 지울 수 없게 하려는 것).
- 등재 시 닉네임을 받는다(최대 8자, localStorage에 기억).
- **주력은 "내 기록", 명예의 전당은 덤이다** (게임 관리자 확정, 2026-08-28):
  - **명예의 전당이 죽어도 게임은 온전해야 한다.** 브로커가 안 붙거나 retain이 비어
    있어도 내 기록은 그대로 뜨고, 랭킹 영역만 조용히 비거나 "지금은 불러올 수 없어요"로
    처리한다. **랭킹 로딩 실패가 게임 진입을 막아서는 안 된다** — 랭킹은 게임 시작
    경로와 완전히 분리해 비동기로 채운다.
  - **한계를 UI에 한 줄 적는다.** README만으로는 부족하다. 명예의 전당 옆에
    "기록이 사라질 수 있고 검증되지 않습니다" 정도를 작게 표기한다.
- 알려진 한계: 기록은 영구 보존되지만 **클라이언트가 자기 점수를 직접 올리는 구조라
  검증되지 않는다.** 그리고 **한 번 올린 기록은 수정·삭제할 수 없다** — 잘못 올려도
  되돌릴 수 없으니 UI에 그대로 적는다.
  ※ 이전에는 공용 MQTT retain 슬롯을 썼는데 브로커가 주기적으로 비워져 기록이
  사흘을 못 넘겼다. 그래서 Firebase 로 옮겼다.

## 8. 멀티플레이 — 한 명 남을 때까지

- **2인 이상**, 상한은 8인. 방 코드(6자)로 입장. 통신 계층은
  `games/ox-survival/index.html`의 3중 브로커 폴백(`makeMqttNet`)을 그대로 가져온다.
- 대기실에서 **방장이 수동으로 시작**한다. 시작 시 방장이 시드와 시작 시각을 뿌리고
  전원 `3 · 2 · 1` 카운트다운 후 동시에 출발한다.
- **층수 상한 없음.** 마지막 한 명이 남을 때까지 계속한다.
- 각자 자기 상태를 **400ms마다** 발행한다: `{pid, name, floor, alive, t}`.
  죽는 순간에는 즉시 1회 더 발행한다. 이 발행이 곧 하트비트다 —
  **6초간 소식이 없으면 이탈로 보고 탈락 처리**(마지막 층수 기록).
  400ms는 출발값이다. 8인이면 초당 20건인데 공용 브로커가 버티는지 **구현 후 실측해
  보고에 적는다.** 순위표가 1초여도 게임은 성립하지만, "지금 누가 몇 층인지"의 긴박감이
  이 게임의 재미라 너무 늦추면 밋밋해진다 — 버거울 때만 낮춘다.
- 화면 오른쪽(모바일은 위쪽)에 **생존자 실시간 순위**를 층수순으로 띄운다.
- 탈락하면 **즉시 관전 모드**로 전환한다. 자기 최종 층수는 고정되고, 남은 사람들의
  경쟁을 계속 본다. 나가기 버튼은 항상 있다.
- **동시 탈락 판정**: 마지막 생존자가 동시에 사라지면 **최종 층수가 높은 쪽이 우승**.
  층수까지 같으면 **공동 우승**으로 처리한다.
- **방장이 나가도 경기는 끝나지 않는다.** 각자의 죽음은 본인만이 보고하고 다툴 여지가
  없으므로, 시작 이후에는 모든 클라이언트가 같은 상태에서 승자를 독립적으로 계산할 수
  있다. 방장 권한은 대기실·시작 신호까지만 필요하다. (OX 서바이벌과 다른 점이다)
- **동일 시드의 부작용 — 관전자가 정답표가 된다** (게임 관리자 지적, 2026-08-28):
  전원이 같은 계단을 오르므로, 먼저 죽은 사람이 옆에서 "다음은 왼쪽!"이라고 불러주면
  그대로 통한다. 같은 방에 있거나 통화 중이면 성립한다. 그래서:
  - **관전 화면에는 생존자의 앞으로 올 계단을 절대 그리지 않는다.** 층수와 생존 여부만
    보여준다. 남의 계단을 그려주면 그게 곧 정답표다.
  - 죽기 전까지 본 구간을 기억하는 것은 막을 수 없다. 이건 신뢰 모델에 포함시킨다.
- **부정 방지는 하지 않는다 (v1).** 두 가지 경로가 열려 있다 —
  ① 공용 MQTT라 마음먹으면 **가짜 층수를 발행**할 수 있고,
  ② 위의 **관전자 코칭·계단 암기**를 막을 수 없다.
  친구끼리 하는 방을 전제로 한다 — OX 서바이벌과 같은 수준의 신뢰 모델이며,
  **이 두 경로를 README에 그대로 적는다.**

## 9. 기술 제약 (게임 관리자 지침, 2026-08-28)

- GitHub Pages 정적 배포, **서버 없음**.
- **`file://` 더블클릭에서 열려야 한다.** ES 모듈 금지, classic script만 쓴다.
  외부 의존은 mqtt.js CDN 하나뿐이고, 그것도 **멀티를 고르거나 명예의 전당을 열 때만**
  불러온다 — **플레이 중에는 네트워크를 전혀 건드리지 않는다**(마피아와 같은 방식).
  ※ 초안에는 "싱글 경로는 네트워크를 전혀 건드리지 않는다"고 적었으나, 사용자가 전체
  순위표를 필수로 확정하면서 싱글에도 통신이 생겼다. 대신 **죽은 뒤에만** 부르도록 미뤄
  플레이 자체는 오프라인으로 유지했다.
- **`crypto.subtle` 제약은 이 게임에 해당하지 않는다.** 마피아·캐치마인드가 https를
  요구한 이유는 직업/정답 같은 **비밀 정보를 암호화**해야 했기 때문이다. 여기서 오가는
  값은 층수와 생존 여부뿐이고 둘 다 원래 전원에게 공개되는 정보라 암호화할 것이 없다.
  방 코드는 `Math.random`으로 만든다. 따라서 멀티도 `file://`에서 동작해야 하며,
  **구현 후 실제로 확인해 결과를 검수 보고에 적는다** (공용 브로커 wss 접속만 되면 된다).
- **`games/stairs/` 밖은 건드리지 않는다.** `data/games.js` 등록은 11절 참고.
- 허브 테마 계승: 배경 `#0a0b12`, 카드 `#161927`, 선 `#262b40`, 텍스트 `#e8eaf2`, 포인트 `#00e5ff`.
- 접근성: 허브 복귀 링크에 `aria-label`, **모든 터치 타깃 44px 이상**(게임 버튼은 96px),
  게이지는 색만으로 상태를 알리지 않고 숫자를 같이 띄운다.
- 콘솔 에러 0, 모바일 375px 폭에서 레이아웃이 깨지지 않을 것.

## 10. 화면 요건

- 캔버스 2D. 계단은 지그재그로 쌓아 올리고 카메라가 따라 오른다(플레이어를 화면 60% 높이에 고정).
- 다크 아케이드 톤 — 허브 `assets/style.css`의 색감과 맞춘다.
- 한 칸 이동 애니메이션 **90ms 이내**. 초당 6.5칸(154ms 간격)을 버텨야 하므로 이보다 길면 안 된다.
- `prefers-reduced-motion` 존중 — 카메라 흔들림·파티클을 끄고 즉시 스냅한다.
- 모바일 세로 우선. 버튼은 엄지가 닿는 하단 절반, 최소 높이 96px.
- 상단 HUD: 층수(크게) + 게이지 바 + 퍼센트 숫자. 멀티는 여기에 생존자 수를 덧붙인다.
- **고도에 따라 하늘이 변한다** — 0층 대기권(푸른빛) → 120층 우주 → 500층 성운 →
  1200층 은하 띠 → 2000층 은하 중심. 층수 자체가 보상이 되도록 하는 장치다.
- **내 최고 기록 층에 금색 표식**을 세운다. 오르는 중에 목표가 보여야 한다.
  넘어서면 소리·파편·안내로 알린다. **100층마다 이정표 계단**에 층수를 새긴다.
- **게이지가 32% 아래로 떨어지면 화면 가장자리가 붉게 맥동한다.**
  색만으로 알리지 않는다 — HUD의 퍼센트 숫자는 그대로 둔다.
- 소리는 Web Audio 로 합성한다(음원 파일 없음). **오른쪽 위 버튼으로 끄고 켜며
  설정은 기억된다.** 브라우저 정책상 첫 입력 전에는 소리가 나지 않는다.

## 11. 버전 기록 (사용자 확정, 2026-08-28)

"버전 기록도 확인할 수 있게" — 게임 안에서 현재 버전과 변경 내역을 볼 수 있어야 한다.
테트리스·OX 서바이벌이 쓰는 방식을 그대로 따른다.

- 파일 안에 `VERSION` 문자열과 `CHANGELOG` 배열(`{v, t:[변경사항…]}`)을 둔다. v1은 `'1.0.0'`.
- 화면에 **`버전 v1.0.0 · 변경 내역`** 칩을 두고, 누르면 시트가 열려 전체 내역을 보여준다.
- **칩은 첫 화면 위쪽, 스크롤 없이 보이는 자리에 둔다.** OX 서바이벌이 v1.3.3에서
  "버튼이 화면 밖에 있어 안 보인다"로 수정한 전례가 있다 — 같은 실수를 반복하지 않는다.
- 첫 화면뿐 아니라 **대기실·게임 오버(결과) 화면에서도** 볼 수 있게 배선한다.
- 닫기 버튼에 `aria-label="닫기"`, 터치 타깃 44px 이상.

## 12. 하지 않는 것 (v1 범위 밖)

- 부활 / 이어하기
- 층수에 따른 계단 패턴 난이도 변화 (난이도는 게이지만 담당)
- 부정 방지·서버 검증
- 프로필/경험치 연동 — RPG 연동은 프로필 화면이 나온 뒤 별건으로 논의

## 13. 허브 등록 (다른 담당 관할)

`data/games.js` 항목 추가는 **메인 홈페이지 담당 관할**이다. 구현이 끝나면 이쪽에서
직접 고치지 않고 게임 관리자를 통해 등록을 요청한다. 제안 항목: `id: 'stairs'`, `title: '무한의 계단'`,
`emoji: '🪜'`, `tags: ['아케이드','반응속도','멀티']`.

## 14. 검수 때 확인할 것

1. 오입력 즉사가 실제로 즉사인가 (판정이 한 칸 밀리지 않는가)
2. 고속 연타 시 입력이 씹히지 않는가 (초당 6회 이상)
3. **300층에서 1초 멈췄을 때 게이지가 정확히 절반쯤 빠지는가** (사용자 확정 기준점)
4. 멀티에서 2인 → 1인 남았을 때 우승 화면이 양쪽 모두에 뜨는가
5. 방장이 탭을 닫아도 남은 사람들의 경기가 계속되는가
6. 탈락자가 관전으로 넘어가고 최종 층수가 고정되는가
7. 모바일 세로에서 버튼이 엄지에 닿고, 오래 눌러도 화면 확대/스크롤이 일어나지 않는가
8. `file://` 더블클릭으로 싱글이 되는가, 그리고 멀티까지 되는가
9. 콘솔 에러 0 / 375px 폭 레이아웃 / 허브 복귀 링크 `aria-label`
10. 브로커를 막아도(오프라인) 싱글이 정상 진입되고 내 기록이 뜨는가 — 랭킹만 비는가
11. 관전 화면에 생존자의 다음 계단이 노출되지 않는가
12. 버전 칩이 첫 화면에서 스크롤 없이 보이는가, 대기실·결과 화면에서도 열리는가
