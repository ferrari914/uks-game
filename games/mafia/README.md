# 마피아 (Englknight)

단일 파일 게임입니다. `index.html` 하나에 HTML·CSS·JS가 전부 들어 있습니다.

- **싱글플레이** — 플레이어 1명 + AI 7명, 8인 클래식전. 외부 라이브러리·네트워크를 일절 쓰지 않아
  `index.html`을 더블클릭해 `file://`로 열어도 그대로 돌아갑니다.
- **멀티플레이** — 실제 유저 4~8인. 방을 만들고 초대 링크를 보내면 됩니다.

스펙: 싱글은 `SPEC.md`, 멀티는 `SPEC_MULTI.md`.

---

## 멀티플레이 구조

서버가 없습니다. **방장 브라우저가 심판(권위)** 이고, 나머지는 공개 MQTT 브로커를 거쳐 대화합니다.
직업 배정, 밤 능력 판정, 투표 집계, 승패 판정을 전부 방장이 계산하고 결과만 뿌립니다.

### 통신
- 브로커: `wss://broker.emqx.io:8084/mqtt` → `broker.hivemq.com:8884` → `test.mosquitto.org:8081` 순차 폴백
- mqtt.js는 CDN(unpkg → jsdelivr)에서 로드하되 **멀티 모드에 들어갈 때만** 받아옵니다.
  싱글플레이는 이 코드를 한 줄도 지나가지 않습니다.
- 방 코드 5자리, 초대 링크는 `<주소>#<코드>`
- 토픽 네임스페이스 `mafia42x/<코드>/…`
  | 토픽 | 내용 |
  |---|---|
  | `state` (retained) | 공개 상태. **직업이 절대 들어가지 않는다.** 생존자·페이즈·타이머·득표 집계 |
  | `pub` | 방장이 뿌리는 공개 로그와 전체 채팅 |
  | `ev` | 참가자 → 방장. `join`/`hb`/`leave`만 평문, 나머지 행동은 전부 암호화 |
  | `p/<pid>` | 방장 → 개인. 조사 결과·치료 성공·방탄 발동·비밀 채팅 (암호화) |
  | `r/<pid>` (retained) | 방장 → 개인. 직업 카드 (암호화) |

### 암호화
각 클라이언트는 입장할 때 WebCrypto로 **RSA-OAEP 2048** 키쌍을 만들고 공개키(JWK)를 `join`에 실어 보냅니다.
방장은 개인 정보를 그 사람의 공개키로 암호화해 보냅니다.
페이로드가 RSA 직접 암호화 한계(190바이트)를 넘으면 **AES-GCM 세션키를 만들어 데이터는 AES로, 세션키만 RSA로** 감쌉니다.

`crypto.subtle`은 보안 컨텍스트(https 또는 localhost)에서만 동작합니다.
그래서 **`file://`로 열면 멀티 버튼이 비활성화**되고 안내 문구가 뜹니다. 배포 주소(https)에서는 문제없습니다.

암·복호화는 전부 비동기라 완료 순서가 발행 순서와 어긋날 수 있습니다.
밤 능력·투표는 순서가 결과를 바꾸므로 **발행용·수신용 Promise 체인 큐(`qSend`/`qRecv`)로 직렬화**했습니다.

### 이 암호화가 막는 것과 막지 못하는 것

**막는 것 — 링크를 받지 않은 제3자의 브로커 도청.**
공개 브로커라 누구나 `mafia42x/<코드>/#` 와일드카드로 전부 구독할 수 있습니다.
그렇게 붙어도 직업은 평문으로 보이지 않습니다. 보이는 건 이름·아바타·생사·페이즈·득표수,
그리고 본인이 스스로 공개한 직업 주장(`claimed`)과 전체 채팅뿐입니다.

**막지 못하는 것 1 — 같이 노는 사람의 치팅.** 클라이언트 코드는 누구나 뜯어볼 수 있습니다.

**막지 못하는 것 2 — 방장은 다 안다.**
방장 브라우저가 심판이라 전체 상태를 들고 있고, 개발자도구를 열면 전원의 정체를 볼 수 있습니다.
서버가 없는 구조에서는 원리적으로 막을 수 없습니다.
서로 아는 사람끼리 하는 게임이라는 전제여서, 사용자 결정(2026-08-28)으로 **게임 화면의 경고 문구는 넣지 않습니다.**
정체 보호가 필요해지면 판정을 맡을 서버(무료 티어 서버리스 함수 등)를 두는 것이 유일한 해결책입니다.

### 방장의 권한
대기실의 `게임 시작`, 종료 후 `한 판 더` — 이 둘뿐입니다.
게임이 시작되면 방장도 다른 참가자와 똑같이 직업을 받고 똑같이 플레이합니다.
**멀티에는 건너뛰기 버튼이 없습니다**(싱글에는 있습니다). 페이즈는 타이머로만 넘어갑니다.
방장 브라우저가 타이머를 소유하는 것은 내부 구현일 뿐 UI 특권이 아닙니다.

### 접속·이탈
- 하트비트 3.5초. 11초간 소식이 없으면 방장이 이탈로 보고, 게임 중이면 **사망 처리**하고 전체에 알립니다.
- 방장이 나가면 방이 닫힙니다. 참가자는 방 닫힘 공지를 받거나, 공지가 못 나간 경우
  **12초간 `state`가 안 오면** 스스로 방이 닫힌 것으로 판단합니다.
- 게임 도중에 같은 코드로 들어오면 관전자로 붙습니다(직업 복구는 범위 밖).

### 백그라운드 탭 대응
브라우저는 숨겨진 탭의 `setInterval`을 1초까지 늘리거나 아예 멈춥니다.
방장이 심판이라 방장 탭이 뒤로 가면 전원의 게임이 멈춥니다.
그래서 진행·하트비트는 **Web Worker 타이머**로 돌립니다(워커는 이 제한을 받지 않습니다).
그래도 멈춘 구간이 생기면, 방장은 멈춰 있던 시간만큼 `endsAt`과 각자의 `seen`을 뒤로 밀어
**판을 건너뛰지 않고 멈췄다 이어서** 진행합니다.

## 통신 계층의 경계 (`LINK`)

게임 로직은 mqtt·토픽 이름·암호화 함수를 직접 부르지 않습니다.
전부 `LINK` 어댑터 하나를 거칩니다. 서버(예: Cloudflare Workers + Durable Objects)로 옮길 때는
`LINK`의 메서드 본문만 갈아끼우면 됩니다.

```
LINK.ready(pid, onNet)        키 생성 + 연결
LINK.setId(pid)               내 식별자
LINK.publicKey()              내 공개키(JWK)
LINK.openHost(code, {onAction})               권위자로 방 열기
LINK.openGuest(code, {onState,onPublic,onPrivate})  참가자로 방 붙기
LINK.setPeerKey(pid, jwk) / LINK.setAuthorityKey(jwk)
LINK.join(name) / heartbeat(name) / leave()
LINK.send(action)             참가자 → 권위자 (암호화)
LINK.pushState(v)             권위자 → 전원 (공개 상태)
LINK.pushPublic(m)            권위자 → 전원 (공개 로그·채팅)
LINK.pushPrivate(pid, o, ret) 권위자 → 개인 (암호화)
LINK.clearPrivate(pid) / closeRoom(text) / close()
```

`LINK` 바깥에서 게임 로직이 쓰는 함수는 `mpSendEv`(내 행동 보내기),
`deliver`(방장이 개인에게), `pubMsg`/`announce`(공개 방송), `hostPublish`(공개 상태) 넷뿐입니다.
