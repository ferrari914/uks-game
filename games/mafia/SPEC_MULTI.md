# 마피아 v2 — 멀티플레이 스펙 (실제 유저끼리 플레이)

> 사용자 지시(2026-08-27): "이 게임은 AI랑 싸우는 게 아니다. OX 퀴즈처럼 실제 유저가 들어와서 하는 게임이다.
> 기존 싱글플레이는 지우지 말고, 처음 화면에서 싱글/멀티를 고를 수 있게 하라."
> v1 스펙(`SPEC.md`)은 **싱글플레이 모드의 스펙으로 그대로 유효**하다. 이 문서는 멀티플레이 추가분이다.

## 0. 최상위 요구사항
1. 진입 시 **모드 선택 화면**: `싱글플레이` / `멀티플레이` 두 개.
2. **싱글플레이는 기존 동작 그대로 유지**한다. 회귀 금지. 외부 CDN 없이 `file://`에서 계속 돌아가야 한다.
3. 멀티 도입으로 바뀌는 문구: 시작 화면의 "AI 7명과 겨루는 8인 클래식전"은
   - 모드 선택 화면 → AI 언급 없이 게임 자체 소개
   - 싱글 카드 → "AI 7명과 겨루는 8인 클래식전"
   - 멀티 카드 → "친구들과 방을 만들어 함께 하는 마피아. 4~8인."

## 1. 통신 계층 — OX 서바이벌과 동일한 방식을 쓴다
`games/ox-survival/index.html`의 `makeMqttNet()` 구조를 그대로 따른다 (검증된 코드다).
- 브로커: `wss://broker.emqx.io:8084/mqtt` → `broker.hivemq.com:8884` → `test.mosquitto.org:8081` 순차 폴백
- mqtt.js는 CDN에서 로드(unpkg → jsdelivr 폴백). **멀티 모드에 들어갈 때만 로드한다.**
  싱글플레이는 네트워크를 일절 건드리지 않는다.
- 방 코드 5자리(대문자+숫자), 초대 링크는 `location.pathname + '#' + code`
- 토픽 네임스페이스: `mafia42x/<code>/...` (OX의 `oxdm5/`와 겹치지 않게)

## 2. 권위 모델 — 방장 브라우저가 심판
OX와 동일하게 **방장(host) 브라우저가 게임 진행의 유일한 권위**다.
직업 배정, 밤 능력 판정, 투표 집계, 승패 판정 전부 방장이 계산하고 결과만 뿌린다.

### 2-1. 여기서 마피아 고유의 문제: 정체 누출
OX는 모든 상태를 공개해도 됐지만 마피아는 안 된다. 두 가지를 반드시 지킨다.

**(A) 공개 상태와 비공개 상태를 토픽으로 분리한다.**
- `mafia42x/<code>/state` (retained) — **직업이 절대 들어가지 않는다.** 생존자 목록, 페이즈, 타이머,
  공개 로그, 투표 집계 결과 등 "모두가 봐도 되는 것"만.
- `mafia42x/<code>/p/<pid>` — 그 사람 전용 정보(내 직업, 마피아 동료, 경찰 조사 결과, 의사 치료 성공,
  군인 방탄 발동, 사망 안내).

**(B) 개인 토픽은 반드시 암호화한다. 이게 이 스펙의 핵심이다.**
공개 브로커는 누구나 `mafia42x/<code>/#` 와일드카드로 구독할 수 있다. 토픽만 나눠서는 전혀 안전하지 않다.
- 각 클라이언트는 입장 시 **WebCrypto로 RSA-OAEP 2048 키쌍을 생성**하고, `join` 이벤트에 **공개키(JWK)** 를 실어 보낸다.
- 방장은 각 플레이어의 개인 정보를 **그 사람의 공개키로 암호화**해서 `p/<pid>`에 publish 한다.
- 페이로드가 RSA 직접 암호화 한계(약 190바이트)를 넘으면 AES-GCM 세션키를 만들어 데이터는 AES로,
  세션키만 RSA로 감싸는 하이브리드로 보낸다.
- WebCrypto는 표준 내장이라 CDN이 필요 없다. **단, `crypto.subtle`은 보안 컨텍스트에서만 동작한다**
  (https 또는 localhost). GitHub Pages는 https라 문제없다. `file://`로 열면 멀티는 안 된다 —
  이 경우 멀티 버튼을 비활성화하고 "멀티플레이는 배포 주소(https)에서만 됩니다"라고 안내한다.
- 밤에 마피아끼리 하는 비밀 채팅도 같은 방식으로 방장이 마피아들에게만 개별 암호화 전송한다.

**(C) 남는 한계 — 방장은 다 안다.** 방장 브라우저에 전체 상태가 있으므로 방장이 개발자도구를 열면
모든 정체를 볼 수 있다. 서버가 없는 이상 원리적으로 못 막는다.

**사용자 결정 (2026-08-27): 방장도 일반 참가자로 게임에 참여한다.**
> "방장도 참여해. 방장은 그냥 게임을 시작할지 말지만 정하는 거고, 게임 들어가면 다른 유저들과 동일한 취급을 받게 해."

따라서:
- **방장 관전(진행자) 모드는 만들지 않는다.** 체크박스도 넣지 않는다.
- **방장의 권한은 딱 두 가지뿐이다**: 대기실에서 `게임 시작`, 종료 후 `한 판 더`.
- **게임이 시작되면 방장은 다른 참가자와 완전히 동일하다.** 진행 관련 특권을 주지 않는다 —
  즉 **멀티에서는 `건너뛰기` 버튼을 아무에게도 주지 않는다**(싱글에는 그대로 둔다).
  페이즈는 타이머로만 넘어간다. 방장 브라우저가 타이머를 소유하되 이는 내부 구현일 뿐 UI 특권이 아니다.
- 위 한계는 숨기지 않는다. **대기실에 "방장 브라우저가 심판 역할을 하므로, 방장이 마음먹으면 정체를 볼 수 있습니다"**
  안내를 명시하고 README에도 같은 내용을 적는다.

## 4. 진행 방식 (멀티)
- 페이즈 타이머는 **방장이 소유**하고 `state`에 남은 시간을 실어 보낸다. 클라이언트는 표시만 한다.
- 밤: 능력 대상 선택을 각자 `ev` 토픽으로 방장에게 보낸다. 마피아는 2명이면 합의 — **마지막에 지정된 대상**이
  최종 반영되고, 마피아끼리는 서로의 선택이 실시간으로 보인다(암호화된 개인 메시지로).
- 낮 토론: 전체 채팅(공개 토픽). 여론조사·시간 연장/단축은 v1과 동일.
- 투표 / 최후의 반론 / 찬반 투표: v1 규칙 동일. 집계는 방장이 한다.
- **멀티에서는 `건너뛰기` 버튼을 두지 않는다** (위 2-C 결정). 페이즈는 타이머로만 넘어간다.
- 사망자 채팅: 사망자 + 영매에게만 암호화 전송.

## 5. 접속·이탈 처리 (OX 방식 준용)
- 대기실: 참가자 목록·방장 표시·초대 링크 복사, 방장만 "게임 시작"(최소 4명)
- 하트비트로 이탈 감지. 게임 중 이탈자는 **사망 처리**하고 전체에 알린다.
- **방장이 나가면 게임을 종료**하고 남은 사람에게 "방장이 나가 게임이 종료되었습니다" 안내
  (호스트 이관은 상태 전체를 넘겨야 해서 v2 범위 밖).
- 재접속: 같은 코드로 다시 들어오면 관전자로 붙는다(직업 복구는 v2 범위 밖).
