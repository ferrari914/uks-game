# 캐치마인드 — 안내

한 명이 제시어를 보고 그림을 그리고, 나머지가 채팅으로 맞히는 실시간 그림 퀴즈입니다.
빌드도, 서버도, 계정도 필요 없습니다. 정적 파일 4개가 전부입니다.

```
games/catchmind/
├─ index.html   마크업 + CSS + 부팅
├─ net.js       MQTT 통신 계층 (방 키 AES-GCM 암복호화 포함)
├─ game.js      게임 로직 (로비/라운드/캔버스/채팅/점수)
└─ words.js     제시어 풀 (window.CM_WORDS)
```

로드 순서는 `words.js` → `net.js` → `game.js`입니다. ES 모듈은 쓰지 않습니다
(`file://`에서 CORS로 막히기 때문입니다).

---

## 노는 순서

1. 한 명이 접속해서 이름·캐릭터를 고르고 **새 방 열고 초대 링크 받기**
2. **초대 링크 복사** → 단톡방에 붙여넣기 (`.../#ABC12-xxxxxxxxxxxxxxxx` 형태)
3. 친구들이 링크를 누르면 "초대받은 방 ABC12" 카드가 뜨고, 이름만 넣고 **바로 입장**
4. 방장이 모드·라운드·제한시간·난이도·카테고리를 고르고 **게임 시작**
5. 차례가 된 사람은 제시어 3개 중 하나를 고르고(10초), 제한시간 동안 그림만 그립니다
6. 나머지는 채팅으로 정답을 맞힙니다. 맞힌 사람은 그 차례 동안 채팅이 잠깁니다

> **방 코드만으로는 입장할 수 없습니다.** 방마다 열쇠(16자)가 따로 있고 그 열쇠는
> 초대 링크 안에만 들어 있습니다. 코드 입력칸에는 `ABC12-열쇠` 전체를 붙여넣으세요.

---

## 규칙

### 라운드
**1 라운드 = 참가자 전원이 한 번씩 출제하는 한 바퀴**입니다 (skribbl.io 방식).
5명이 3라운드를 하면 총 15차례입니다. 설정 화면의 라운드 버튼 아래에 예상 소요 시간이
같이 나옵니다 — 10라운드가 얼마나 긴지 미리 보라는 뜻입니다.

**인원이 몇 명이든 자동으로 시작하지 않습니다. 방장이 눌러야 시작합니다.**

| 모드 | 시작 조건 |
|---|---|
| 개인전 | 2명 이상 (최대 8명) |
| 팀전 | 4명 이상 + 레드·블루 인원이 같을 것 (2:2 / 3:3 / 4:4) |

팀전에서는 **출제자와 같은 팀원만 정답을 맞힐 수 있습니다.** 상대팀이 입력한 말은
일반 채팅으로 처리되고, 제시어가 섞여 있으면 `●●●`로 가려집니다.

### 점수
| 대상 | 계산 |
|---|---|
| 정답자 | `40 + 반올림(60 × 남은시간 ÷ 제한시간)` → 40~100점 |
| 정답 순위 보너스 | 1등 +15, 2등 +10, 3등 +5 |
| 출제자 | 맞힌 사람 1명당 +20점 (아무도 못 맞히면 0점) |

출제자도 득점하므로 **잘 그려서 맞히게 하는 쪽이 이득**입니다.

### 힌트 (켜기/끄기)
켜면 처음부터 글자 수가 `_ _ _`로 보이고, 남은 시간 60% 지점과 30% 지점에
한 글자씩 공개됩니다(최대 `글자수 - 1`자까지).

## 동작 방식

참가자끼리는 공용 MQTT 브로커(WebSocket)로 연결됩니다. 순서대로 시도하며 앞의 것이
막히면 자동으로 다음으로 넘어갑니다.

1. `broker.emqx.io`
2. `broker.hivemq.com`
3. `test.mosquitto.org`

**연결된 뒤에 끊긴 경우에도 다음 브로커로 옮겨갑니다.** 공용 브로커는 IP당 연결 제한이나
주기적인 강제 절단이 흔한데, 같은 브로커로만 재시도하면 영영 못 붙기 때문입니다.
12초 안에 재접속이 안 되면 다음 브로커로 옮기고 구독을 다시 겁니다. 방장이 옮겨가면
참가자도 방장을 찾아 브로커를 훑어 따라갑니다. 이 과정에서 **15~30초쯤 화면이 멈춘 것처럼
보일 수 있습니다** — 상단 띠에 "다른 서버로 옮겨 봅니다"가 뜨는 동안은 기다리면 됩니다.
목록을 세 바퀴 돌아도 못 붙으면 "브로커에 연결할 수 없습니다" 안내가 뜹니다.

**방장의 브라우저가 심판입니다.** 턴 진행, 타이머, 정답 판정, 점수 계산을 전부 방장
기기에서 하고 결과만 나머지에게 뿌립니다.

토픽은 4개입니다.

| 토픽 | 방향 | 내용 |
|---|---|---|
| `ekcm/<코드>/s` | 방장 → 전원 | 상태(retain) · 채팅/시스템 메시지 |
| `ekcm/<코드>/c` | 참가자 → 방장 | join · ping(3초) · chat · team · pick · sync · leave |
| `ekcm/<코드>/d` | 출제자 → 전원 | 드로잉 |
| `ekcm/<코드>/p/<uid>` | 방장 → 개인 | 제시어 후보, "아깝다" 안내 |

드로잉은 **80ms 배치**로 모아 보내고, 배치 하나에 좌표쌍 40개까지만 담습니다.
직전 점과 2px(논리좌표) 안 떨어진 점은 버립니다. 좌표는 0~1 정규화 실수(소수 3자리)로
보내므로 기기 해상도가 달라도 같은 그림이 나옵니다. 늦게 들어온 사람은 출제자에게
지금까지의 스트로크 스냅샷을 요청해 화면을 맞춥니다.

### 방 키 암호화
방을 만들 때 16자짜리 **방 키**가 생성되고, 초대 링크 안에만 실립니다.
**방 키는 MQTT로 전송되지 않습니다.** `net.js`가 모든 페이로드를 이 키에서 유도한
AES-GCM 키로 암복호화합니다(브라우저 내장 `crypto.subtle` — 라이브러리가 늘지 않습니다).
복호화에 실패한 메시지는 조용히 버리므로 다른 방 트래픽이 자동으로 걸러집니다.

`crypto.subtle`은 보안 컨텍스트(HTTPS)에서만 동작합니다. `wss://` 때문에 어차피
HTTPS가 전제이므로 폴백은 만들지 않았습니다.

## 치팅에 대한 정직한 한계

서버가 없으므로 **결심한 사람의 치팅은 막을 수 없습니다.** 과장하지 않고 그대로 적습니다.

1. **`words.js`는 모든 참가자에게 전송됩니다.** 제시어 풀 전체가 공개돼 있으므로,
   힌트(글자 수·공개된 글자)로 후보를 좁히면 개발자도구 없이도 찍을 수 있습니다.
   제시어를 해시로 보내는 식의 대책은 **의미가 없습니다** — 공격자가 공개된 풀 전체를
   같은 방식으로 해시해 맞춰보면 되기 때문입니다.
2. **방장은 심판이라 정답을 알 수밖에 없습니다.** 정답 판정을 방장 기기에서 하는 구조상
   방장이 출제자가 아닌 차례에도 방장 브라우저에는 제시어가 존재합니다. 서버 없이 이걸
   없앨 방법은 없습니다.
3. **링크를 받은 사람은 개발자도구로 방 키와 제시어를 볼 수 있습니다.** AES-GCM 암호화가
   막는 것은 **링크를 받지 않은 제3자의 브로커 도청**뿐이고, 같이 노는 사람의 치팅은
   못 막습니다.
4. 그래서 v1이 실제로 막는 것은 **우발적·저비용 노출**뿐입니다: 제시어를 전원 토픽에
   싣지 않고, 페이로드를 방 키로 가리고, 정답 채팅 원문을 뿌리지 않습니다.
5. 결론: **친구끼리 즐기는 용도입니다.** 상금이 걸린 자리에는 쓰지 마세요.

## 알아둘 점

- **HTTPS가 필수입니다.** WebSocket이 `wss://`이고 `crypto.subtle`도 보안 컨텍스트가
  필요해서, `http://`나 `file://`로 열면 멀티플레이가 되지 않습니다. 이때도 화면은 정상적으로
  뜨고 "멀티플레이는 https 주소에서만 됩니다" 안내가 보입니다.
- **방장이 창을 닫으면 방이 닫힙니다.** 참가자 화면에는 "방이 닫혔습니다" 안내가 뜹니다.
- **잠깐 다른 탭을 봐도 방에서 빠지지 않습니다.** 브라우저는 숨은 탭의 타이머를 늦추기
  때문에, 응답이 12초 넘게 없으면 목록에 **"자리 비움"**으로만 표시하고 점수와 출제 순서는
  그대로 둡니다. 돌아오면 즉시 원래대로 돌아옵니다. 50초가 넘어가야 비로소 목록에서 빠집니다.
- 자리를 비운 사람이 **출제자 차례**였다면 그림이 멈춰 다들 기다리게 되므로 **그 차례는
  무효 처리**(아무도 득점하지 않음)되고 다음 차례로 넘어갑니다. 목록에서 빠지지는 않으니
  돌아오면 다음 차례부터 다시 참여합니다. 자리 비운 사람은 정답 판정과 "전원 정답 시 조기
  종료" 계산에서 빠집니다.
- **방장 자신의 회선이 끊긴 동안에는 이 판정을 멈춥니다.** 내 인터넷이 잠깐 끊겼다고
  참가자들이 통째로 튕겨 나가면 안 되기 때문입니다.
- **연결이 끊기면 최대 30초쯤 멈췄다가 저절로 돌아옵니다.** 상단 띠에 "다른 서버로 옮겨
  봅니다"가 떠 있는 동안은 기다리면 됩니다.
- 남은 인원이 2명 미만이 되면 게임을 중단하고 대기실로 돌아갑니다.
- 게임 도중 들어온 사람은 관전하다가 **다음 라운드부터** 0점으로 합류합니다.
- 이름·그림·채팅은 같은 방 사람들에게 그대로 보입니다. 민감한 내용은 넣지 마세요.
- 방장 설정(모드·라운드·시간·난이도·카테고리·힌트)은 브라우저에 저장돼 다음 판에 복원됩니다.

## 제시어 추가하기

`words.js`의 `window.CM_WORDS` 배열에 한 줄 추가하면 끝입니다.

```js
{ w:'고양이', c:'동물', d:1, a:['냐옹이'] },
```

| 필드 | 뜻 |
|---|---|
| `w` | 제시어 (한글 6자 이내 권장) |
| `c` | 카테고리 (`window.CM_CATEGORIES`에 있는 값) |
| `d` | 난이도 — 1 쉬움 / 2 보통 / 3 어려움 |
| `a` | 별칭 배열 (선택). 여기 적힌 말도 정답으로 인정합니다 |

`words.js`를 불러오지 못하면 방을 만들 수 없고, 홈 화면에 "제시어 데이터를 불러오지
못했습니다" 안내가 뜹니다.
