# 공용 랭킹 규격 — 명예의 전당 / 주간 / 일간

> 게임 관리자 작성 · 2026-09-01
> 사용자 지시: *"모든 게임을 영구 보존하는 랭킹과, 일주일 단위·하루 단위로 초기화되는
> 랭킹을 구축해줘. 영구적으로 기록이 남는 '명예의 전당'과 일주일 랭킹, 하루 랭킹."*

## ⚠ 2026-09-02 변경 — 자동 등재로 바뀌었다

사용자 지시: *"일일이 수동으로 랭킹에 올리지 말고 모든 기록을 하루·일주일 랭킹에
자동으로 올려라. 그중 최고점을 명예의 전당으로. 이름을 모르면 시작할 때 이름을 받아라.
한 사람당 하나의 기록만 있어야 한다."*

**등재 버튼을 없애고 게임이 끝나면 `RANK.autoSubmit` 을 부른다.**

```js
RANK.autoSubmit('내게임id', 점수).then(function(r){
  // r.sent   올렸는지
  // r.reason 화면에 그대로 써도 되는 한 줄
});
```

### 왜 "모든 기록"을 그대로 올리지 않는가
**기록은 수정도 삭제도 안 된다.** 게임이 끝날 때마다 무조건 쓰면 한 사람이 하루에
수백 줄을 쌓고, 순위표를 뽑을 때 **그 사람 기록만 받아와 20위를 못 채운다.**

그래서 `autoSubmit` 은 **자기 기록을 갱신했을 때만** 실제로 보낸다. 사용자가 보기에는
자동이고, 쌓이는 것은 의미 있는 기록뿐이다. 기준은 셋 — 오늘 최고 · 이번 주 최고 ·
역대 최고. **셋 중 하나만 넘어도 올린다**(기록 하나가 세 랭킹에 전부 들어가므로 한 번만
쓰면 된다). 어제 역대 9999점을 냈어도 오늘 100점이면 **오늘 랭킹 1등이므로 올라간다.**

기준은 이 기기에만 남는다. 다른 기기에서 처음 하면 한 번 더 올라가고, 그건 순위판이
이름으로 접어 준다. **로그인이 없는 한 이게 최선이다.**

### 이름은 시작 전에 받는다
자동 등재라 **끝난 뒤에 이름을 물을 자리가 없다.** 이름이 없으면 시작 화면에서 받는다.

```js
if(!RANK.name()){ /* 이름 입력칸을 보여주고 시작 버튼을 막는다 */ }
var c = RANK.setName(입력값);          // {ok, name, error}
if(!c.ok) 화면에 c.error 를 보여준다;   // 12자 제한·빈 이름
```

**이름 다듬기는 `RANK.cleanName` 하나만 쓴다.** 게임마다 규칙이 다르면 같은 사람이
여러 줄로 갈라진다. 이름은 게임 사이에 공유된다 — 한 번 적으면 다른 게임에서도 쓴다.
**게임 쪽에 따로 검사를 두지 말 것** — 한쪽에서 막은 이름이 다른 쪽에서 통과하면
같은 순위표에 그 이름이 그대로 뜬다.

`cleanName` 이 막는 것: 빈 이름 · 12자 초과 · 제어문자 · 비속어(띄어쓰기·대소문자 회피 포함).
비속어 목록은 테트리스가 쓰던 것을 옮겨왔다. **이건 악의적 우회를 막는 장치가 아니다** —
우회하려는 사람은 목록을 몰라도 REST 로 직접 넣는다. 목적은 평범한 사용자가 실수로
험한 이름을 올리는 것을 막는 것이고, 그래서 목록이 공개돼도 잃을 게 없다.
자모 분리나 유사 문자는 못 잡는다.

### 한 사람당 한 줄
순위판이 같은 이름을 접는다. **이름은 신원이 아니다** — 다른 사람이 같은 이름을 쓰면
합쳐진다. 화면에 그 사실을 적어 둔다(순위판이 직접 적는다).

**다만 접는 것에 기대지 말 것.** 접히는 것은 화면일 뿐이고 기록은 영구히 남는다.
**판이 끝났을 때만 부르는 것**이 먼저다.

테트리스가 좋은 예다. 부활이 있는 게임이라 게임오버마다 부르면 부활 전 점수와 부활 후
점수가 각각 올라가 **한 판에 두 줄**이 생긴다. 그래서 부활 여지가 없을 때와 부활을
포기·실패했을 때, 판이 진짜 끝나는 두 곳에서만 부른다.

담당의 정리를 그대로 옮긴다:

> 부활 전 점수는 부활 후 점수에 **흡수되는 중간값**이라 남길 이유 자체가 없다.
> 이름으로 접는 방식은 "같은 사람의 **서로 다른 판**"을 정리하는 장치인데,
> 부활 건은 애초에 판이 하나다.

**두 문제는 다르다.** 중간값은 접어야 할 기록이 아니라 애초에 기록이 아니다.

전부 들어 있다. **각자 구현하지 말 것** — 아래 "왜"를 읽어 보라.

## 왜 공용으로 두는가

기록은 **영구 보존이고 아무도 지울 수 없다**(그게 남의 기록을 지키는 방법이다).
그래서 스키마를 게임마다 다르게 쓰면, 나중에 통합 순위나 프로필 연동을 만들 때
**이미 쌓인 기록을 고칠 방법이 없다.** 되돌릴 수 없는 것은 처음에 한 벌로 정해야 한다.

그래서 스키마와 질의는 이 파일 하나에만 둔다. 게임은 `submit`과 `board`만 부른다.

## 저장 구조

기록 **하나**가 세 랭킹에 전부 쓰인다. 중복 저장하지 않는다.

```
/ranking/<게임id>/<자동키> = {
  name:  "홍길동",                  // 12자까지
  score: 12345,                     // 0 ~ 99,999,999
  ts:    1788249219724,
  dk:    "2026-09-01|00012345",     // 그날(KST) + 8자리 0채움 점수
  wk:    "2026-08-31|00012345"      // 그 주 월요일(KST) + 같은 점수
}
```

### 날짜와 점수를 왜 한 문자열에 붙이나
Firebase 실시간 DB는 **한 질의에 정렬 기준을 하나만** 쓴다. "오늘 것 중 높은 순 20개"를
서버에서 뽑으려면 날짜와 점수가 한 필드에 있어야 한다. 점수를 같은 자릿수로 0을 채우면
문자열 순서가 곧 숫자 순서가 된다 (`00000009 < 00000100 < 99999999`).

이렇게 안 하면 **오늘 기록을 전부 내려받아 브라우저에서 정렬**해야 한다. 지금은 기록이
적어서 티가 안 나지만, 쌓일수록 느려지고 데이터도 낭비된다.

### 초기화는 삭제가 아니다
날짜가 바뀌면 **새 칸에 쌓이기 시작하고 어제 칸은 그대로 남는다.** 규칙상 아무도
기록을 지울 수 없으므로 이 방식이어야 한다. 덤으로 지난 날짜 순위를 나중에 꺼내볼 수 있다.

### 기준 시간은 한국 시간(KST) 고정
하루는 **KST 자정**, 한 주는 **KST 월요일 자정**에 바뀐다. 브라우저 시계를 쓰지 않는다 —
해외 접속자와 국내 접속자가 다른 칸에 들어가면 순위가 갈라진다.

## API

| 부르는 것 | 하는 일 |
|---|---|
| `RANK.autoSubmit(game, score)` | **자동 등재(기본).** 갱신했을 때만 보낸다. `{sent, reason, best}` |
| `RANK.name()` / `RANK.setName(s)` / `RANK.cleanName(s)` | 이름 저장·다듬기. 게임 사이 공유 |
| `RANK.submit(game, {name, score})` | 수동 등재(하위호환). 직접 부를 일은 거의 없다 |
| `RANK.submit(game, {name, score, extra:{level:9}})` | 게임 고유 정보 추가 (테트리스 `level`·`lines` 처럼) |
| `RANK.top(game, 'all'\|'week'\|'day', n)` | 순위 배열. 직접 그리고 싶을 때 |
| `RANK.board(el, game, opts)` | 탭 3개 순위판을 통째로 그린다 |
| `RANK.nextReset('day'\|'week')` | 다음 초기화 시각(Date) |

`board`의 `opts`
- `n` 몇 위까지 (기본 20)
- `unit` 점수 뒤 단위 — 무한의 계단이면 `'층'` (기본 `'점'`)
- `format` 점수를 직접 꾸밀 때 `function(score, rec) → 문자열`
- `me` 내 기록 id. 그 줄이 강조된다

순위판 CSS는 `.rk-*` 클래스로 나간다. 색은 CSS 변수 `--rk-hi`(강조)·`--rk-line`(선)·
`--rk-dim`(흐린 글씨)·`--rk-me`(내 기록)를 게임 쪽에서 덮어쓰면 된다.

## ⚠ 검증할 때 — 자동 등재로 바뀌면서 위험이 달라졌다

수동 등재 시절에는 **등재 버튼을 안 누르면 그만**이었다. 지금은 **게임을 켠 채로 두기만 해도
죽으면서 자동으로 올라간다.** 그리고 기록은 **아무도 지울 수 없다.**

실제로 이 사고가 세 번 났다 — 게임 관리자가 규칙을 실측하다 `x / 1점` 을 `/scores` 와
`/ranking/stairs` 양쪽에 만들었고, 무한의 계단 담당이 화면만 찍고 게임을 켜둔 사이
`손님검증 5층` 이 올라갔다. 셋 다 영구히 남는다.

**검증은 이렇게 한다.**
1. **게임 id 를 `__selftest` 같은 시험용으로 바꿔** 부른다. 어느 게임도 그 경로를 읽지 않는다
2. 실제 게임 화면을 봐야 하면 **개인기록을 미리 심어** 자동 등재가 문턱에 걸리게 한다
   (`localStorage['rank.best.<게임>.<이름>'] = '{"day":9999,"week":9999,"all":9999}'`)
3. 그것도 어려우면 **`fetch` 를 감싸 가짜 응답을 돌려준다** — 배선과 화면을 전부 확인하면서
   쓰기만 막을 수 있다
4. **확인이 끝나면 게임을 끄고 창을 닫는다.** 켜둔 채로 두면 게이지가 닳아 죽는다

## 반드시 지킬 것

1. **화면에 한계를 적는다.** 서버가 없어서 점수를 검증할 방법이 없다.
   > 점수는 검증되지 않습니다 — 누구나 기록을 보낼 수 있습니다.
   > 한 번 올린 기록은 수정·삭제할 수 없습니다.
2. **DB 주소를 게임 코드에 직접 쓰지 않는다.** `ranking.js`만 알고 있으면 된다.
3. **`name`/`score`/`ts`/`dk`/`wk` 다섯 이름은 `extra`로 덮어쓸 수 없다.** 덮으면 랭킹이 깨진다.
4. **`file://` 에서도 동작한다.** `Origin: null` 요청에 서버가 CORS를 허용하는 것을
   실측 확인했다. 외부 스크립트·SDK·API 키가 필요 없다.

## 이미 랭킹이 있는 두 게임

| 게임 | 지금 | 할 일 |
|---|---|---|
| **무한의 계단** | `/ranking/stairs`, 스키마 동일 | `ranking.js`로 교체. **기존 기록은 그대로 명예의 전당에 남는다** (`dk`/`wk`가 없어 주간·일간에만 안 뜬다 — 옛 기록이니 맞는 동작) |
| **테트리스** | `/scores`, 스키마 다름(`level`·`lines`·`best`) | **쓰기는 `/ranking/tetris` 한 곳으로 옮긴다** — 기존 `/scores` 쓰기는 없앤다. 명예의 전당만 `board`의 `extraAll` 갈고리로 옛 17건을 합쳐 읽는다. `extra:{level, lines}` 로 기존 정보를 유지할 것 |

> **두 곳에 쓰지 말 것.** 처음에 "양쪽에 쓰자"고 정했다가 테트리스 담당이 잡아냈다.
> 기록은 지울 수도 고칠 수도 없으므로 **쓰기가 한쪽만 성공하면 그 불일치가 영구히 남는다** —
> 주간에는 있는데 명예의 전당에는 없는 기록이 생기고 되돌릴 방법이 없다.
> 게다가 합쳐서 읽으면 새 기록이 두 번 뜬다. **기록 하나는 정확히 한 군데에만 있어야 한다.**

## 남의 코드를 가져다 쓸 때 — 실제 사례

**계층을 복사하면 그 계층을 *쓰는 쪽* 코드도 함께 읽어야 한다.**

영어 끝말잇기가 온라인 멀티를 붙이며 `games/catchmind/net.js`(전송 계층)를 그대로
가져왔다. 로직을 손대지 않은 것 자체는 옳은 판단이었다 — 검증된 코드를 다시 짤 이유가 없다.
그런데 **그 계층을 쓰는 쪽인 `catchmind/game.js`의 대응 코드는 안 가져왔다.**
같은 뿌리의 결함이 다섯 번 나왔다.

1. **배경 탭 방어 누락** — 숨은 탭의 침묵을 이탈로 판정해 멀쩡한 참가자를 쫓아냈다
2. **브로커 반복 탐색 누락** — 한 번만 훑고 포기했다. 한 번 끊기면 양쪽이 각자 다른 브로커에 앉는다
3. **복귀 유예 기준점 오류** — 원본은 "탐색 시작"에 거는 유예를 "끊김 확정"에 걸어, 돌아온 뒤 7초 만에 튕겼다
4. **retain 무력화** — 브로커가 남긴 죽은 방장의 낡은 상태를 생존 신호로 받았다
5. **생존 판정과 화면 갱신의 분리** — 4번을 고칠 때 생존 판정만 걸러 화면은 과거로 되돌아갔다

**이 파일(`ranking.js`)도 같은 함정이 있다.** 가져다 쓰기만 하면 되게 만들었지만,
`submit`/`board`가 무엇을 전제하는지(KST 고정, 0채움 자릿수, 색인 필요) 모르고 쓰면
어긋난다. **위 "반드시 지킬 것"을 읽고 쓸 것.**
