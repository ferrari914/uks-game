# UK's Game 메인 홈페이지 제작 가이드라인 (v1)

작성: 총괄 관리자 / 대상: 메인 홈페이지 담당
이 문서 기준으로 제작하고, 총괄 검수도 이 문서 기준으로 진행한다.

## 1. 목적과 원칙
- 방문자가 **3초 안에** "게임 모음 사이트"임을 알고, **클릭 2번 안에** 게임 플레이에 도달해야 한다.
- 주인공은 게임 카드다. 장식·애니메이션이 카드 가독성과 클릭 동선을 방해하면 안 된다.
- 게임 추가/삭제는 `data/games.js` 수정만으로 반영되어야 한다 (index.html에 게임 하드코딩 금지).

## 2. 유지할 것 (기존 강점)
- `window.GAMES` 기반 데이터 렌더링, 검색, 태그 필터, ready/wip 상태 구분
- 다크 아케이드 테마, CSS 변수 팔레트 체계
- `file://` 더블클릭 실행 호환: 데이터는 `<script src>` 방식 유지, `fetch()` 사용 금지

## 3. 디자인
- 다크 배경 + 네온 포인트 컬러는 **1~2색으로 절제**. 모든 요소가 빛나면 아무것도 안 빛나 보인다.
- 간격은 일관된 스케일(예: 4/8/12/16/24/32px)로. 임의 값 남발 금지.
- hover/focus 시 시각 피드백 필수 (카드 lift, 테두리 강조 등). 단 transform·opacity 위주로 가볍게.
- 무한 반복 애니메이션·과한 글리치 효과 금지. 장식(스캔라인 등)은 텍스트 대비를 해치지 않는 강도로.
- 이모지+그라데이션 썸네일 체계는 이번 단계에서 유지 (이미지 교체는 별도 백로그).

## 4. 레이아웃 / 반응형
- 카드 그리드: 모바일 1열, 태블릿 2열, 데스크톱 3~4열 (`auto-fill` + `minmax` 권장).
- 터치 타깃 최소 44×44px. 모바일에서 검색창·필터 칩이 한 손으로 조작 가능할 것.
- 가로 스크롤이 페이지 전체에 생기면 안 된다 (375px 폭 기준 확인).

## 5. UX 세부
- 검색어 + 태그 필터는 **동시에(AND)** 적용된다.
- 결과 0건일 때 빈 화면이 아니라 안내 문구를 보여준다 (예: "조건에 맞는 게임이 없어요").
- `status: "wip"` 게임: 클릭 이동 차단 + "준비중" 표시를 카드에서 즉시 알 수 있게.
- `status: "ready"` 게임: 카드 전체가 클릭 영역. 이동은 상대경로(`games/<id>/`) 유지.
- 게임 수가 늘어도(10개+) 깨지지 않는 구조로.

## 6. 접근성
- 시맨틱 마크업: header/main/nav, 카드 링크는 `<a>`, 필터는 버튼 요소.
- 키보드만으로 검색→필터→카드 진입까지 가능해야 하고, `:focus-visible` 스타일 제공.
- 본문 텍스트 대비 4.5:1 이상. 네온색을 본문 텍스트에 쓰지 않는다.
- 썸네일 이모지에 의미 전달을 의존하지 않는다 (제목 텍스트가 항상 존재).
- `prefers-reduced-motion` 시 애니메이션 제거/축소.

## 7. 성능 / 기술 제약
- 외부 라이브러리·프레임워크·CDN 의존 금지. 바닐라 HTML/CSS/JS만.
- 파일 구조 유지: `index.html` + `assets/style.css` + `data/games.js`. 파일 추가가 필요하면 총괄에 먼저 보고.
- `data/games.js` 기존 스키마(id/title/desc/path/emoji/color/tags/status/added)는 유지. 필드 추가는 기존 항목이 없어도 동작하게(하위호환).
- 콘솔 에러·경고 0. 게임 폴더(`games/*`) 내부는 절대 수정하지 않는다.
